# TESTING-ru.md

# Руководство по тестированию

В этом документе описана инфраструктура тестирования проекта `gentk`.

## Организация тестов

- `tests/common.rs` – вспомогательный модуль, предоставляющий функцию `run_gentk` для запуска бинарного файла с автоматическим добавлением флага `--yes`.
- `tests/integration.rs` – интеграционные тесты, покрывающие все команды генераторов, JSON-вывод, страницы справки, создание конфигурации и вывод версии.
- `tests/fixtures/full_config.json` – образец конфигурационного файла (пока не используется в автоматических тестах).

## Запуск тестов

```bash
cargo test
```

Все тесты являются интеграционными и запускаются стандартной командой `cargo test`. Модульные тесты на данный момент отсутствуют.

## Структура тестов

### `tests/common.rs`

Содержит одну публичную функцию:

- `run_gentk(args: &[&str]) -> assert_cmd::Command`  
  Возвращает настроенный экземпляр `assert_cmd::Command` для запуска бинарного файла `gentk` с заданными аргументами. Если флаг `--yes` ещё не присутствует в аргументах, он добавляется автоматически, чтобы избежать блокировки на запросах подтверждения.

### `tests/integration.rs`

Определяет константу `ALL_COMMANDS` – массив кортежей `(имя_подкоманды, дополнительные_аргументы)` для всех команд, которые можно протестировать без обязательных параметров (например, `uuid5` требует `--namespace` и `--name`, они передаются в `extra_args`).

Шесть тестовых функций:

- `all_commands_generate_one_value` – проверяет, что каждая команда с количеством 1 завершается успешно и выдаёт непустой вывод.
- `all_commands_json_single` – проверяет, что флаг `--json` с одним значением формирует JSON, содержащий `"value":`.
- `all_commands_json_multiple` – проверяет, что флаг `--json` с несколькими значениями формирует JSON, содержащий `"values":`.
- `all_commands_help` – запускает `--help` для каждой команды и проверяет успешное завершение.
- `config_command_with_yes_creates_file` – создаёт временный каталог, выполняет `config --yes` внутри него и проверяет, что файл `gentk.json` был создан.
- `version_flag` – запускает `--version` и проверяет, что вывод содержит `"gentk"`.

## Добавление нового генератора

Чтобы расширить тестовый набор для новой команды:

1. Добавьте реализацию команды в `src/commands/`.
2. Добавьте вариант в перечисление `Commands` в `src/cli/parser.rs` и обновите `CommandFactory`.
3. В `tests/integration.rs` добавьте кортеж в массив `ALL_COMMANDS`:
    - Если команда не требует дополнительных аргументов (например, `ulid`), используйте `("ulid", &[])`.
    - Если требует (например, `uuid5`), передайте их как `&["--namespace=dns", "--name=test"]`.

Все общие тесты (справка, JSON, генерация) автоматически выполнятся для новой команды. Дополнительный тестовый код не требуется.

## Зависимости для тестов

- `assert_cmd` – для запуска бинарного файла и проверки результата.
- `predicates` – для гибких утверждений о выводе.
- `tempfile` – для временных каталогов в изолированных тестах.

Они объявлены в `[dev-dependencies]` файла `Cargo.toml`.

## Режим без подтверждений (headless)

Глобальный флаг `--yes` используется для пропуска запросов подтверждения (например, при перезаписи конфигурационного файла). Вспомогательная функция `run_gentk` автоматически добавляет `--yes`, если он ещё не указан. Это позволяет всем тестам выполняться без вмешательства пользователя.
